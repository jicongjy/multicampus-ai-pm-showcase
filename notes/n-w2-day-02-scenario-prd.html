3. 내 실습 — 올리브영 앱 구매 흐름 [실습]

아래 내용 중 앱에서 직접 확인된 것은 "본인 인증이 없다"는 점뿐이고, 나머지 화면명·버튼 이름·시스템 처리·메뉴 위치는 [추정] 이다.

3-1. 성공 시나리오 5차 (사용자 행동 + 시스템 처리, 19단계)

No.시나리오
1사용자는 떨어진 선크림을 사려고 올리브영 앱을 실행해 홈 화면을 확인한다.
2사용자는 홈 화면 상단 검색창에 '선크림'을 입력해 검색한다.
3시스템은 입력한 검색어와 맞는 상품을 찾아 검색 결과 화면에 보여 준다.
4사용자는 검색 결과 화면에서 리뷰와 가격을 비교해 마음에 드는 상품을 선택한다.
5사용자는 상품 상세 화면에서 용량, 가격, 리뷰를 확인한다.
6사용자는 상품 상세 화면에서 상품을 장바구니에 담는다.
7시스템은 선택한 상품을 사용자의 장바구니에 저장한다.
8사용자는 장바구니 화면에서 수량과 상품 금액을 확인한다.
9사용자는 장바구니 화면에서 주문 버튼을 눌러 주문/결제 화면으로 이동한다.
10사용자는 주문/결제 화면에서 보유한 쿠폰을 선택해 적용한다.
11시스템은 쿠폰의 사용 조건을 확인하고 할인 금액을 반영해 최종 결제 금액을 다시 계산한다.
12사용자는 주문/결제 화면에서 포인트 사용 금액을 입력해 적용한다.
13시스템은 사용 가능한 포인트인지 확인하고 최종 결제 금액에 반영한다.
14사용자는 주문/결제 화면에서 배송지가 집 주소와 맞는지 확인한다.
15사용자는 주문/결제 화면에서 결제 수단을 선택해 결제한다.
16시스템은 결제 수단 회사에 결제 승인을 요청하고 승인 결과를 받는다.
17시스템은 승인이 되면 주문 정보를 서버에 저장하고 상품 재고를 차감한다.
18시스템은 주문 완료 화면에 주문번호와 도착 예정일을 보여 준다.
19사용자는 주문 완료 화면에서 도착 예정일을 확인한다.

버전 이력: 3차(13단계, 본인 인증 줄 포함) → 4차(12단계, 본인 인증 삭제) → 5차(19단계, 시스템 처리 7줄 추가)

약점·리스크

  • 시스템 줄 7개(3, 7, 11, 13, 16, 17, 18번)는 쇼핑앱 일반 구조에 기댄 추정. 특히 재고 차감 시점은 모른다.
  • 로그인 시점을 모른다. 1번에 로그인을 넣지 않았다.
  • 실패·예외 시나리오는 아직 작성하지 않았다. 번호가 바뀔 때마다 실패 케이스 번호를 다시 맞춰야 한다.

3-2. IA (엑셀, v0.1 → v0.2)

  • v0.1: 화면 6개 — 올리브영 온라인몰 홈, 검색 결과, 상품 상세, 장바구니, 주문/결제, 주문 완료
  • v0.2: 화면 23개 (17개 추가)
  • 탐색: 검색 화면, 카테고리 화면, 카테고리 상품 목록, 오늘드림, 선물하기, 바코드 스캔, 매장 찾기
  • 주문 하위: 쿠폰 선택, 배송지 변경, 결제 수단 선택
  • 마이: 마이, 주문 내역, 주문 상세, 상품평 작성, 쿠폰함, 고객센터, 1:1 문의
  • 검색으로 확인된 것: 앱에 바코드 스캔, 주변 매장 조회, 선물하기, 상품평 사진 첨부, 1:1 문의 기능이 있다는 점까지.
  • [추정]: 메뉴 위치, 화면 이름, Depth 계층 전부. 바코드 스캔·매장 찾기를 홈 바로 아래에 둔 것은 근거 없음. 장바구니를 Depth2에 둔 것도 추정.
  • [주의] 오늘드림 설명은 2019년 기사에 근거해 현재 서비스와 다를 수 있음.
  • 23개 중 시나리오와 무관한 화면(오늘드림, 선물하기, 고객센터 등)이 절반 가까이라, 줄이라는 피드백을 받을 수 있음. 5단계 허용 여부도 모름.

3-3. 프로토타입 HTML 4종 (클로드 디자인 대화) [미검증]

파일내용
통합프로토타입 v0.1홈 → 결제 완료까지 눌러 볼 수 있는 흐름, 값 연결, 시스템 동작 로그
로우파이 v0.1같은 흐름의 와이어프레임(X 상자, 회색 버튼, 점선)
하이파이 v0.1모노톤 + Pretendard 마감, 쿠폰 하단 시트, 완료 체크 애니메이션
스켈레톤UI v0.16개 화면의 로딩 상태를 한 페이지에 나란히 배치, 완성 화면과 비교 토글
  • 확인된 것: 가상 브라우저(jsdom)로 동작·글자 내용을 시험했고 자바스크립트 오류는 없었다.
  • [미검증]: 모양(배치, 간격, 색)과 애니메이션은 눈으로 확인하지 못함.
  • 상품명·평점·리뷰·배송지·재고·쿠폰 조건·승인 거절 조건은 지어낸 가상 샘플이며 실제 올리브영 규칙이 아니다.
  • 배운 점: 클로드 디자인 캔버스는 한 보드 안에서 상태가 바뀌는 구조라, 스켈레톤(1.2초), 담기 알림(2.6초), 승인 대기(약 3.5초) 같은 중간 화면은 순간적으로 지나가 따로 볼 수 없었다. 해결책으로 A(상태별 정지 화면 보드)와 B(화면 바로가기 버튼)가 제시됐다. 이후 스켈레톤 시안을 별도 파일로 만들어 보완했다.
