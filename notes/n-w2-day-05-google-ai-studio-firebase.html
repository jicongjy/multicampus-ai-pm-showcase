4. 직접 실습: 이벤트 신청폼 관리자 페이지

4-1. 만든 것

신청서와 관리자 페이지를 한 HTML 파일로 합쳐 만들었습니다. 한 번에 다 넣지 않고 기능을 하나씩 추가하며 확인했습니다.

  • 신청서: 접수 완료 화면, 같은 번호로 다시 신청하면 "이미 신청된 번호입니다." 안내
  • 관리자 입장: 비밀번호를 입력해야 들어갈 수 있는 화면
  • 관리자 CRUD: 신청 추가, 조회(기간 선택, 검색, 페이지 넘김), 수정, 삭제, 전체 삭제
  • 개인정보 표시: 이름, 전화번호, 이메일, 전달 사항은 일부를 가려서 표시
  • 개인정보 수집 이용 동의: 신청서에서는 필수로 받았지만 저장되지 않던 누락을 직접 발견해 고쳤고, 관리자 표에 "개인정보 동의" 열이 생겼습니다.

4-2. 개선하면서 내린 결정

  1. 관리자 화면에 불필요한 카드가 많고 간격이 넓어 스크롤이 길었습니다. 카드를 없애고 요약을 한 줄로 줄였으며, 그래프도 작은 막대로 줄였습니다.
  2. 데이터와 다른 정보가 섞여 있어서 "현황"과 "신청 명단" 두 영역으로 나누고, 각 영역을 접고 펼 수 있게 했습니다.
  3. 상단 제목, 탭 칩, 하단 관리 영역의 좌우 여백이 서로 달라서 같은 값으로 맞췄습니다.

4-3. 고민하고 정한 기준

정보를 마스킹하기 때문에 어떤 항목을 식별자로 둘지 고민했습니다. 관리자가 한 화면 안에서 원하는 정보를 한 번에 빠르게 파악하는 것을 최우선으로 두었고, 그래서 디자인과 간격을 최소화했습니다. AI로 만들면 블록으로 조합된 UI가 많이 나오는데, 내역과 리스트를 보고 관리하는 입장에서는 블록이 꼭 필요하지 않은 경우가 많다는 점을 알게 되었습니다.

관리자 페이지에서 지킬 기준은 다음과 같이 정리했습니다.

  • CSV 전체 다운로드 기능은 필수
  • AI가 낸 결과는 반드시 검증하고 확인하며 하나씩 개선
  • 데이터가 두 줄로 늘어지거나 좌우 스크롤이 생기지 않게 하는 가독성
  • 상단 그래프 등은 크게 차지하지 않게 구성

7. 겪은 문제

  • AI 스튜디오 무료 일일 한도가 소진되어 오후에 결과가 나오지 않는 경우가 있었습니다. 대안은 다른 계정으로 진행하거나, 소스 코드를 깃허브에 올려 두고 클로드나 챗지피티에서 이어서 작업하는 방법입니다.
  • 공유 링크는 시크릿 창(깃허브 비로그인 상태)에서 열어 보면 다른 사람 입장에서 보이는지 더블 체크할 수 있습니다.
  • 배포한 사이트에서 신청해도 오류가 나거나 관리자 페이지나 시트가 안 되는 경우에는 오류 문장을 그대로 AI에게 붙여 원인을 묻는 방식으로 접근합니다.
