내 실습: 혜택 구간(C파트) 개선

만든 이벤트 페이지의 혜택 카드 3장(할인·쿠폰·사은품)과 이벤트 기간 줄을 계속 고쳤습니다.

가상 값 표시: 화면에 넣은 최대 30%, 5,000원, 미니 캔들 세트, 이벤트 기간 2026-12-16 ~ 2026-12-31은 모두 지어낸 값입니다. 실제 정책이 아닙니다.

진행 순서

  1. 카드를 더 눈에 띄게 만들기 (그라데이션, 빛이 훑고 지나가는 효과, 아이콘 움직임)
  2. 자리표시자로 비워 둔 값을 가상 값으로 채우기
  3. 이벤트 기간에 가상 날짜 넣기
  4. 개선 제안서(PDF)와 번호 표시 이미지 만들기
  5. 카드에 레드 포인트와 움직임 적용 (클로드가 처음에는 이벤트 기간 줄로 잘못 이해해 그곳에 넣었다가 카드에 다시 적용)
  6. 이벤트 기간 줄의 레드 포인트 삭제

개선 제안 6가지 (아직 페이지에 반영하지 않았고, 효과는 모두 검증 전 가설입니다)

  1. 이벤트 기간 옆에 '시작까지 D-n' 표시
  2. 대표 혜택 하나만 밝게 강조
  3. 숫자가 0에서 올라가는 카운트업
  4. 구간에 들어오면 카드가 순서대로 등장
  5. 모바일 탭 반응
  6. 카드마다 '이 혜택 받기' 버튼 (신청 버튼이 5곳에서 8곳으로 늘어나는 문제가 있음)
  • 색상과 애니메이션을 한 번에 요청했습니다. 결과가 어느 쪽 때문인지 가르기 어렵습니다.
  • '그대로 둘 것'과 위치 지정이 약해서 레드가 엉뚱한 줄에 들어갔다가 지워졌습니다.
  • 클로드가 화면을 열어 확인하지 못한 채 결과를 보고했습니다. 미리보기는 제가 직접 열어 확인해야 합니다.
  • 화면에 효과를 재는 코드가 없어서 신청 완료율을 지금은 잴 수 없습니다.
  • 휴대폰 화면은 아직 확인하지 못했습니다.

별도 실습: 다낭 연말 여행 상품 비교표

  • 가격이 세 곳에 흩어져 있던 것을 '기본 가격 + 추가 비용 = 예상 총비용' 계산서 모양으로 모았습니다.
  • 포함 항목은 ✓/✕ 표로 줄을 맞췄습니다.
  • 앞서 정한 '추천·점수·순위는 넣지 말 것'과 👍 요청이 충돌했고, 항목별 사실 표현만 쓰는 절충안을 냈습니다. 이 절충이 맞는지는 결정하지 못했습니다.
  • 구조를 통째로 바꿔서, 무엇 때문에 좋아졌는지는 가를 수 없습니다.
  • 모바일 폭으로 저장한 이미지에서 줄바꿈이 어색한 곳이 두 군데 있었습니다. 정보가 많으면 모바일 배치가 어렵다는 말이 실제로 보인 사례였습니다.
